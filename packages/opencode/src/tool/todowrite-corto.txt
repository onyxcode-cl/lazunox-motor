Create and maintain a structured task list for the session; it shows progress to the user.

Use it for work with 3+ distinct steps, several user tasks, or an explicit request for a todo list; capture new instructions as todos. Skip it for a single straightforward task (or <3 trivial steps) and for informational or conversational requests. When in doubt, use it.

States: `pending`, `in_progress` (exactly ONE at a time; more are reduced to the first), `completed`, `cancelled`. Update in real time, never in batches: mark `in_progress` before starting, `completed` only after the work and its verification are done (never on intent). Add follow-ups as you find them; if blocked or partial, keep it `in_progress` and add a todo for the blocker. Keep user-provided commands verbatim; items specific and actionable.

Optional fields (leave out unless needed):
- `verificar`: how to prove it is done. `$ <command>` runs with normal shell permissions when you mark it `completed` (non-zero exit keeps it `in_progress` and shows the output); any other text is a note for you.
- `bloqueado`: `true` when it cannot move; say why in a follow-up todo.
- `id` / `depende_de`: ONLY for real dependencies (ids of this list that must be `completed` first), not for a plain sequence. Cycles or unknown ids reject the list.
